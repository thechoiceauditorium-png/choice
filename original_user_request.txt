# Build Prompt: The Choice Auditorium — Operations Dashboard

You are building a complete, production-ready web application for **The Choice Auditorium**, a marriage/event auditorium in Alamaram, Kanjikode, Palakkad, Kerala. Build this end-to-end — all pages, logic, and data layer — using **HTML, CSS, and vanilla JavaScript** as the primary stack.

## 0. Important tech-stack note before you start

Pure HTML/CSS/JS with no backend (e.g. only `localStorage`) will **not** satisfy the core requirement, because the 5 users are in different physical locations (including outside India) and all need to see the *same live data* — bookings, ledger, attendance, notifications must sync in real time across devices. Recommended approach:

- Frontend: HTML + CSS + vanilla JS (no framework), organized as a multi-page or single-page app.
- Backend/data layer: **Firebase (Firestore + Auth)** — chosen because it needs zero server maintenance, has a generous free tier suitable for this scale (5 users, low volume), and integrates with plain JS via the Firebase Web SDK (`<script type="module">` imports, no build step required). Use Firestore's `onSnapshot` listeners for real-time sync (so a booking added by one owner instantly appears for everyone else — this is what solves the double-booking problem).
- If Firebase is not acceptable, Supabase (Postgres + Realtime) is the alternative — same reasoning, swap accordingly. Default to Firebase unless told otherwise.
- Keep all business logic in plain JS modules; do not introduce React/Vue/build tooling.
